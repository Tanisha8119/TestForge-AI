# TestForge AI Scripts

Optional, explicitly-invoked helper scripts. TestForge AI never runs these automatically —
they exist for a developer (or the agent, with explicit user approval) to call when the
user wants Azure Boards intake or PR publishing on top of the core test-generation workflow.

## fetch-azure-workitem.ps1

Fetches a work item's Title, Description, Acceptance Criteria, State, and Tags from
Azure Boards and prints/saves it as a natural-language scenario that can be pasted
into a TestForge AI request.

```powershell
$env:AZURE_DEVOPS_PAT = "<personal access token with Work Items (Read) scope>"
.\fetch-azure-workitem.ps1 -Organization contoso -Project MyApp -WorkItemId 12345
```

This does not write anything back to Azure Boards; it is read-only intake.

## create-github-pr.ps1

Commits the tests already generated by TestForge AI in the working tree, pushes a new
branch, and opens a GitHub pull request via the `gh` CLI. Run this only after reviewing
the generated tests and only when the user has explicitly asked for a PR.

```powershell
.\create-github-pr.ps1 -CommitMessage "Add tests for login form" -Body "Generated by TestForge AI"
```

Requires `git` and an authenticated `gh` CLI (`gh auth login`).

## Security notes

- PATs and tokens must be supplied via environment variables, never as command-line
  arguments, and never committed to source control or logs.
- These scripts do not store, transmit, or log credentials beyond the single API/CLI
  call that needs them.
